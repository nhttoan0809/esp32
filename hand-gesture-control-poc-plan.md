# Hand Gesture Control PoC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a browser-based proof of concept that uses MediaPipe Hand Landmarker to detect hand gestures from a webcam and map them to simulated IoT device actions, with a clean path to ESP32 integration.

**Architecture:** The browser captures webcam frames and sends them to MediaPipe Hand Landmarker, which produces 21 hand landmarks. A separate rule-based gesture recognition layer converts landmarks into gestures, then an action-mapping layer converts gestures into device actions. The initial PoC simulates an IoT device in the UI; a later integration can replace or extend the action transport with WebSocket or MQTT to control an ESP32.

**Tech Stack:** React, TypeScript, Vite, MediaPipe Tasks Vision, browser MediaDevices/Webcam API, Canvas API, CSS or TailwindCSS.

**Spec:** `docs/superpowers/specs/2026-09-15-hand-gesture-control-poc-design.md`

## Global Constraints

- Run hand tracking directly in the browser; no AI backend or model server for the initial PoC.
- Use MediaPipe Hand Landmarker for hand landmark detection.
- Support one hand first.
- Recognize four initial gestures: `OPEN_PALM`, `FIST`, `THUMBS_UP`, and `POINT`.
- Keep hand tracking, gesture recognition, and action mapping as separate modules.
- The initial device is a simulated IoT device in the web UI.
- Do not introduce ESP32/network integration until the browser-only PoC is stable.
- Add temporal smoothing/debouncing so noisy frame-to-frame predictions do not cause repeated or unstable actions.
- Keep the architecture extensible for later WebSocket or MQTT integration.

### Task 6: Implement finger-state detection

**Files:**
- Modify: `src/gesture/landmarks.ts`
- Create: `src/gesture/gestures.ts`

The first classifier should use simple geometric relationships rather than a second AI model.

Conceptual rules:

```text
Open finger:
    fingertip is farther from the palm/base than the corresponding PIP/DIP relationship indicates.

Closed finger:
    fingertip is folded toward the palm.

Thumb:
    use thumb-to-index/palm geometry and thumb joint orientation.
```

- [ ] Implement functions that determine whether each finger is extended.
- [ ] Prefer normalized geometric measurements over hard-coded pixel distances.
- [ ] Keep thresholds centralized in `gestures.ts`.
- [ ] Account for the mirrored webcam view when interpreting left/right orientation.
- [ ] Test the helper functions with synthetic landmark coordinates.

## 11. Future ESP32 Integration

This is explicitly outside the first browser-only milestone.

The architecture should allow:

```text
                   Browser
                      │
             MediaPipe + Gesture
                      │
               Action Mapper
                      │
             ┌────────┴────────┐
             │                 │
          Web UI            Transport
                               │
                     ┌─────────┴─────────┐
                     │                   │
                 WebSocket             MQTT
                     │                   │
                   ESP32                Broker
                     │
                   GPIO
                     │
                LED / Relay
```

A future transport interface can be:

```ts
type DeviceTransport = {
  send: (action: DeviceAction) => Promise<void> | void;
  disconnect?: () => void;
};
```

The browser gesture pipeline should remain unchanged when switching from the local simulator to ESP32.

Recommended next hardware milestone:

```text
Browser
   ↓
Gesture
   ↓
WebSocket
   ↓
ESP32
   ↓
GPIO
   ↓
LED
```

Only after that should the project evaluate MQTT, remote access, authentication, and production IoT architecture.

## 13. PoC Success Criteria

The most important technical success criterion is not visual polish. It is proving this complete chain reliably:

```text
REAL HUMAN HAND
      ↓
WEBCAM
      ↓
MEDIAPIPE
      ↓
21 LANDMARKS
      ↓
RULE-BASED GESTURE RECOGNITION
      ↓
STABLE GESTURE
      ↓
DEVICE ACTION
      ↓
SIMULATED IoT DEVICE
```

Once this works reliably, the computer-vision portion of the PoC is proven and the next experiment can focus exclusively on communicating the resulting action to an ESP32.
